# Вечерний отчёт — Google Apps Script

Скрипт для Google Таблиц: собирает цифры с вкладок мониторинга
(`Сводная`, `Выводы`, `Нагрузка L2`, `Нагрузка L1`, `Нагрузка Fraud`,
`Зависшие тикеты`) в текстовый шаблон и показывает его в диалоговом окне
с кнопкой «Скопировать».

## Установка

### Вариант А — вручную (без установки ничего на компьютер)

1. Откройте вашу таблицу → **Расширения → Apps Script**.
2. Удалите пустой `Code.gs`, который создаётся по умолчанию.
3. Создайте файл `Code.gs` и вставьте содержимое `src/Code.gs`.
4. Создайте HTML-файл `Dialog` (Файл → Создать → HTML) и вставьте
   содержимое `src/Dialog.html`.
5. Сохраните проект и перезагрузите таблицу.
6. В таблице появится меню **«Вечерний отчёт» → «Сформировать отчёт…»**.

### Вариант Б — через clasp

```bash
npm install -g @google/clasp
clasp login
clasp create --type sheets --title "Вечерний отчёт" --rootDir ./src
clasp push
```
Затем откройте таблицу, которую создаст clasp, или привяжите проект к
уже существующей таблице через `clasp clone <scriptId>` с указанием
её Script ID (Расширения → Apps Script → Настройки проекта).

## Как пользоваться

В меню **«Вечерний отчёт»** два пункта: **«Сформировать отчёт…»**
(собирает вечерний текст) и **«Поиск аномалий…»** (ищет всплески в
процентных метриках, см. раздел ниже).

### Сформировать отчёт

1. Меню **Вечерний отчёт → Сформировать отчёт…**
2. Проверьте поле «Дата (сегодня)» (по умолчанию — сегодня).
3. Заполните поля, которых нет в таблице: ссылку на чат, «Ожидают
   ответа», «Массовый Approved», «Ошибка - Статус», «Проблемные
   области».
4. В разделе «Вторые значения (после «/»)» впишите вручную вторые
   числа для строк API/PSP/BT M/SMP M/L2/L1/L1/Fraud/Зависшие/In
   Progress — таблица даёт только первое число в каждой такой строке,
   второе всегда вводится руками.
5. Нажмите **«Сформировать отчёт»** — текст соберётся в поле снизу.
   Если для какого-то авто-поля в таблице не нашлась строка или ячейка
   на нужную дату оказалась пустой, под текстом появится жёлтое
   предупреждение со списком таких полей — на их месте в тексте будет
   пусто.
6. При необходимости поправьте текст прямо в поле, нажмите
   **«Скопировать»**.

## Как используется дата

Поле «Дата (сегодня)» задаёт ОДНУ дату — саму дату отчёта. От неё
скрипт сам считает нужный столбец в таблице:

- «Создано тикетов (API/BT/PSP/SMP) за прошлый день» — итог за уже
  завершённый день, поэтому берётся из столбца **вчера** (дата минус 1).
- Все остальные автополя (Нагрузка по процессам, L1, Fraud, Зависшие
  (24+), In Progress, BT/SMP Sent/New 72h+) — это снимок текущей
  очереди/нагрузки, поэтому берутся из столбца **сегодня** (сама
  выбранная дата).

Ограничение: если выбрать 1-е число месяца, «вчера» попадёт на
последний день ПРЕДЫДУЩЕГО месяца — а вкладки в этой таблице устроены
по одному месяцу на весь диапазон C:AG. Для 1-го числа поле «Создано
тикетов» скорее всего придёт пустым (с предупреждением) — впишите
его тогда вручную.

- API (Team A/B) → «Нагрузка L2», строка 10 «Суммарная нагрузка "API"»
- PSP → «Нагрузка L2», строка «Суммарная нагрузка "PSP"»
- BT M → «Нагрузка L2», строка 16 «Суммарная нагрузка "BT M"»
- SMP M → «Нагрузка L2», строка «Суммарная нагрузка "SMP M"»
- L2/L1 (депозиты) → «Нагрузка L2», сумма строки 84 («L2/L1 Mena 1x» →
  «Суммарное кол-во Депозиты») и строки 93 («L2/L1 Mena Leads 1x» →

## Поиск аномалий

Меню **Вечерний отчёт → Поиск аномалий…**. Скрипт проходит по всем
процентным строкам книги и показывает те, что в выбранный день заметно
выбились из своей нормы.

### Что считается аномалией

Для каждой процентной строки берутся её же значения за предыдущие дни
месяца, по ним считается медиана и типичный разброс (MAD). Строка
попадает в список, если значение выбранного дня одновременно:

- отстоит от медианы больше чем на минимальный порог (чтобы не ловить
  шум на мелких числах), и
- отстоит сильнее, чем эта строка обычно колеблется.

Норма считается для каждой строки отдельно, поэтому для стабильной
метрики всплеском будет и небольшое отклонение, а для «дёрганой» —
только крупное. Плановых и целевых значений в книге нет, так что
сравнивать не с чем, кроме собственной истории метрики.

Если строка весь месяц простояла на одном значении, разброс равен нулю
и работает один порог отклонения — иначе прыжок с 0 % до 40 % остался
бы незамеченным. В списке такая строка помечена `z = ∞`.

Пустая ячейка в истории не считается нулём, а просто не попадает в
выборку. Это важно для строк с дырами и для стран, подключённых в
середине месяца.

**Чувствительность** переключается тремя уровнями: «Низкая — только
явные», «Средняя» (по умолчанию) и «Высокая — показать всё». Уровень
меняет оба порога сразу.

**В первые дни месяца результатов почти не будет:** строке нужно хотя бы
5 дней истории. Сколько строк пропущено по этой причине, видно в строке
сводки под кнопкой.

### Какие листы проверяются

Все листы, где в шапке (строка 2) есть дневная разметка — сейчас это 15
листов, включая `API`, `BT M`, `PSP`, `SMP`, `ЗТ по ГЕО API`,
`Переключения` и `Трафик + Конверсия`. Разная раскладка столбцов
(C..AG, D..AH, E..AI и парные столбцы «трафик / конверсия»)
определяется автоматически.

Строки **не** прописаны в коде номерами: книга заводится заново каждый
месяц, и вставка одного блока сдвинула бы все номера. Скрипт находит
процентные строки по формату ячеек. Поэтому при смене месяца править
ничего не нужно — но если захочется свериться, в редакторе скриптов
есть служебная функция `debugListPercentRows()`: она печатает в лог всё,
что нашла, по листам и строкам.

Листы без дневной оси (`Время реакции и Время закрытия`, `Время между
цепочками статусов`, `Время обработки`, `Время обработки1`, `Календарь
событий`) в проверку не попадают: там недели и сводные таблицы, а
сравнение идёт по дням. Лист с данными за другой месяц пропускается с
предупреждением.

### Подсветка

Кнопка **«Подсветить в таблице»** заливает найденные ячейки цветом.
**Это меняет общую таблицу — заливку увидят все, кто её откроет.** Пока
кнопка не нажата, скрипт в таблице ничего не трогает.

Кнопка **«Убрать подсветку»** возвращает ячейкам прежние цвета: перед
заливкой скрипт запоминает, какой цвет был у каждой ячейки. Если кто-то
успел перекрасить ячейку вручную, она останется как есть — чужую правку
скрипт не затирает.

Повторный поиск и повторная подсветка старую заливку снимают
автоматически, так что подсвеченный набор всегда один. Нажать «Убрать
подсветку» второй раз подряд — не ошибка, просто сообщение, что убирать
нечего.

### Первый запуск

Подсветка запоминает прежние цвета через хранилище документа, поэтому
при первом запуске после обновления Google один раз попросит заново
разрешить скрипту доступ. Это ожидаемо.
