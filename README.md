# Вечерний отчёт — Google Apps Script

Скрипт для Google Таблиц: собирает цифры с вкладок мониторинга
(`Сводная`, `Нагрузка L2`, `Нагрузка L1`, `Нагрузка Fraud`,
`Зависшие тикеты`), считает выводы по сторонней таблице и показывает
готовый текст в диалоговом окне с кнопкой «Скопировать».

## Установка

### Вариант А — вручную (без установки ничего на компьютер)

1. Откройте вашу таблицу → **Расширения → Apps Script**.
2. Удалите пустой `Code.gs`, который создаётся по умолчанию.
3. Создайте файл `Code.gs` и вставьте содержимое `src/Code.gs`.
4. Создайте HTML-файл `Dialog` (Файл → Создать → HTML) и вставьте
   содержимое `src/Dialog.html`.
5. Сохраните проект и перезагрузите таблицу.
6. В таблице появится меню **«Вечерний отчёт» → «Сформировать отчёт…»**.

**Оба файла обновляйте вместе.** Дата отчёта считается в диалоге, и
серверной функции для неё больше нет: если заменить только `Code.gs`,
старый `Dialog` не сможет подставить дату, и поле останется пустым.

### Вариант Б — через clasp

```bash
npm install -g @google/clasp
clasp login
clasp create --type sheets --title "Вечерний отчёт" --rootDir ./src
clasp push
```
Затем откройте таблицу, которую создаст clasp, или привяжите проект к
уже существующей таблице через `clasp clone <scriptId>` с указанием
её Script ID (Расширения → Apps Script → Настройки проекта).

### Доступ к таблице выводов

Скрипт читает стороннюю книгу «Выводы L2 PS | 2026», поэтому при первом
запуске Google попросит разрешение на доступ к другим таблицам. У
аккаунта, под которым работает скрипт, должны быть права на чтение этой
книги — иначе формирование отчёта упадёт с понятной ошибкой.

## Как пользоваться

1. Меню **Вечерний отчёт → Сформировать отчёт…**
2. Проверьте поле «Дата» (по умолчанию — сегодня).
3. Впишите «Выводы L1-L2» — это число прибавится к выводам, которые
   скрипт посчитает сам.
4. Заполните вечерние данные — вторые числа в строках с «/» по блокам
   «Нагрузка по процессам», «Fraud», «L1», «Зависшие (24+)» и «72h+».
   Таблица даёт только первое число в каждой такой строке.
5. Заполните остальные ручные поля: «Чат 72», «Ожидают ответа»
   (количество и ссылки), «Массовый Approved», «Ошибка - Статус»,
   «Проблемные области».
6. Нажмите **«Сформировать отчёт»**. Под текстом появятся жёлтые
   предупреждения, если какое-то авто-поле не нашлось в таблице — на его
   месте в тексте будет пусто.
7. При необходимости поправьте текст прямо в поле и нажмите
   **«Скопировать»**.

## Как используется дата

Поле «Дата» задаёт ОДНУ дату — саму дату отчёта. По умолчанию
подставляется дата **вашего компьютера**, а не сервера: часовой пояс
проекта (`Europe/Moscow` в манифесте) вечером уже переваливает за
полночь, и серверная дата показывала бы завтрашнее число — при UTC+1 это
начиналось после 22:00 по местному времени, то есть ровно тогда, когда
отчёт и делается. Поэтому дата считается в браузере.

От выбранной даты скрипт сам считает нужный столбец в таблице:

- «Создано тикетов (API/BT/PSP/SMP) за прошлый день» — итог за уже
  завершённый день, поэтому берётся из столбца **вчера** (дата минус 1).
- Все остальные автополя (Нагрузка по процессам, L1, Fraud, Зависшие
  (24+), In Progress, BT/SMP Sent/New 72h+) — это снимок текущей
  очереди/нагрузки, поэтому берутся из столбца **сегодня** (сама
  выбранная дата).

**Первое число месяца.** Вкладки устроены по одному месяцу на диапазон
C:AG, поэтому «вчера» для 1-го числа лежит в предыдущей месячной
таблице. Скрипт туда не ходит: «Создано тикетов» остаётся пустым, а в
предупреждениях появляется отдельная строка об этом. Впишите значение
руками.

## Откуда берутся выводы

Строка «Выводы (MENA 1X / Leads 1X)» складывается из двух частей:
подсчёта по сторонней таблице и ручного поля «Выводы L1-L2».

Источник задан константой в начале `src/Code.gs`:

```js
var WITHDRAWALS_SOURCE = {
  spreadsheetId: '…',
  monthSheets: ['январь', 'февраль', …, 'декабрь']
};
```

`spreadsheetId` указывает на **книгу целиком**, а не на отдельный месяц.
`countWithdrawalsByDate_` обходит все листы книги, оставляет те, чьё имя
совпадает с названием месяца, находит в первых 10 строках столбец
«Дата фиксации» и считает строки, где эта дата равна дате отчёта.
Каждая подходящая строка даёт +1, включая дубли; статусы, суммы и
уникальность ID не учитываются. Исходная таблица не изменяется.

Поскольку обходятся все месячные листы, строка посчитается даже если её
занесли в лист не того месяца.

### Что может сломаться при смене месяца

- **Название нового листа.** Сравнение идёт на точное равенство (регистр
  и пробелы по краям нормализуются). `Ноябрь` и `ноябрь ` подойдут, а
  `Ноябрь 2026`, `Ноя` или `11` — нет, лист будет пропущен. Ошибки при
  этом не будет: остальные месяцы на месте, выводов за нужную дату не
  найдётся, и в отчёте окажется `Выводы: 0` без каких-либо признаков
  проблемы. Перед первым отчётом в новом месяце проверьте, что лист
  назван ровно названием месяца.
- **Заголовок «Дата фиксации».** Ищется в первых 10 строках, точным
  совпадением — `Дата фиксации:` с двоеточием уже не подойдёт. Если
  заголовка нет или он встречается дважды, скрипт остановится с ошибкой
  и назовёт лист. Пустой новый лист (меньше 3 строк) просто пропускается.
- **Даты, вбитые руками.** Понимаются объекты-даты, серийные числа,
  `ГГГГ-ММ-ДД`, `ДД.ММ.ГГГГ` и `ДД/ММ/ГГГГ` — везде год из четырёх цифр.
  `01.11.26` или `1 ноября` остановят формирование отчёта с указанием
  листа и строки.
- **Смена года.** Книга называется «| 2026». Если на следующий год
  завести отдельную книгу, прошитый `spreadsheetId` останется на старой,
  и выводы молча станут нулём. Тогда нужно будет поправить константу.

## Откуда берётся первое число в каждой строке

Скрипт ищет строки не по фиксированным адресам ячеек, а по тексту
подписи в столбце B — это делает его устойчивым к добавлению строк
выше нужной. Ниже — сверенный с реальной таблицей список источников.

- API (Team A/B) → «Нагрузка L2», строка 10 «Суммарная нагрузка "API"»
- PSP → «Нагрузка L2», строка «Суммарная нагрузка "PSP"»
- BT M → «Нагрузка L2», строка 16 «Суммарная нагрузка "BT M"»
- SMP M → «Нагрузка L2», строка «Суммарная нагрузка "SMP M"»
- L2/L1 (депозиты) → «Нагрузка L2», сумма строки 84 («L2/L1 Mena 1x» →
  «Суммарное кол-во Депозиты») и строки 93 («L2/L1 Mena Leads 1x» →
  «Суммарное кол-во Депозиты»); пустая ячейка считается нулём
- L1: Нагрузка → «Нагрузка L1», строка 5 «Cуммарное кол-во нагрузки»
- Fraud: Нагрузка → «Нагрузка Fraud», строка 5 «Cуммарное кол-во нагрузки»
- Зависшие PSP/API → «Зависшие тикеты», сумма строки 13 (API) и
  строки 15 (PSP)
- Зависшие BT M → «Зависшие тикеты», сумма строки 25 и строки 35
  («PT 24 часа (ПК)» в блоках Mena 1x и Mena Leads 1x)
- Зависшие SMP M → «Зависшие тикеты», строка 16 «SMP M»
- In Progress (BT/SMP) → «Зависшие тикеты», сумма строк 23, 33 и 43
  («PT 24 часа In Progress» в блоках Mena 1x, Mena Leads 1x и SMP)
- BT Sent for processing 72h+ → «Зависшие тикеты», сумма строк
  «BT Sent for processing (M) 72h+» в блоках Mena 1x и Mena Leads 1x;
  второе число (после «/») — вручную
- BT New request 72h+ → «Зависшие тикеты», сумма строк
  «New request (M) 72h+» в блоках Mena 1x и Mena Leads 1x; второе
  число (после «/») — вручную
- SMP Sent for processing 72h+ → «Зависшие тикеты», строка «SMP Sent
  for processing 72h+»; второе число (после «/») — вручную
- SMP New Request 72h+ → «Зависшие тикеты», строка «New request 72h+»;
  второе число (после «/») — вручную
